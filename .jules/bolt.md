## 2024-05-18 - Avoid lazy-loading anchor link targets in SPAs
**Learning:** When code-splitting single-page applications (SPAs) that rely on native HTML anchor links (e.g., `href="#section-id"`) for navigation, conditional lazy-loading (e.g., using `IntersectionObserver` to completely defer the rendering of sections until they are scrolled into view) breaks navigation links on initial load. The browser cannot scroll to an element with an id that doesn't yet exist in the DOM. However, standard `React.lazy()` with `<Suspense>` splits the bundle and starts loading the chunk immediately on initial render, inserting the target DOM nodes as soon as the chunk loads. Because the chunk is fetched and rendered in parallel (or almost immediately after initial load), the target DOM nodes are usually present by the time a user tries to click an anchor link, or shortly thereafter, meaning standard lazy loading is generally safe, while scroll-based lazy loading is NOT safe for anchor targets.
**Action:** Use `React.lazy()` for bundle splitting route-like sections, but do not use `IntersectionObserver` to conditionally render sections that are targeted by anchor links. Ensure `React.lazy()` chunks are rendered unconditionally so they start loading immediately.
